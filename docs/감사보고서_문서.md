# 🛡️ Tipping 코드 감사 보고서 (Code Audit Report)

**감사 일자:** 2025년 12월 19일
**감사자:** Senior Software Engineer (GitHub Copilot)
**심각도 범례:** 🔴 Critical (즉시 수정), 🟠 High (배포 전 수정), 🟡 Medium (추후 개선), 🟢 Low (참고)

---

## 1. 보안 (Security)

### 🔴 1.1 JWT 만료 및 갱신 메커니즘 부재
*   **위치:** [`server/controllers/authController.js`](../server/controllers/authController.js)
*   **문제:** Access Token의 유효기간이 `1d`(1일)로 설정되어 있으며, Refresh Token 메커니즘이 없습니다.
*   **위험:** 토큰이 탈취될 경우 24시간 동안 공격자가 계정을 사용할 수 있습니다. 또한 사용자는 하루마다 강제 로그아웃됩니다.
*   **권고:** Access Token 수명을 줄이고(예: 1시간), Refresh Token을 도입하여 보안과 편의성을 모두 잡아야 합니다.

### 🟠 1.2 CORS 설정의 구체성 부족
*   **위치:** [`server/index.js`](../server/index.js)
*   **문제:** `app.use(cors());`로 설정되어 있어 모든 도메인에서의 요청을 허용할 가능성이 높습니다.
*   **위험:** 악의적인 사이트에서 API를 호출할 수 있습니다.
*   **권고:** `origin` 옵션을 사용하여 클라이언트 도메인(Vercel, GitHub Pages)만 명시적으로 허용해야 합니다.

### 🟡 1.3 API 키 노출 위험
*   **위치:** [`client/src/main.jsx`](../client/src/main.jsx), [`client/src/pages/Login.jsx`](../client/src/pages/Login.jsx)
*   **문제:** `VITE_GOOGLE_CLIENT_ID`, `VITE_KAKAO_JAVASCRIPT_KEY` 등이 클라이언트 코드에 포함됩니다.
*   **위험:** 이는 프론트엔드 특성상 불가피하지만, 해당 키들이 악용되지 않도록 각 플랫폼(Google Cloud Console, Kakao Developers)에서 **도메인 화이트리스트(Referer 제한)** 설정을 반드시 해야 합니다.

---

## 2. 코드 품질 및 유지보수성 (Code Quality)

### 🟠 2.1 거대 컨트롤러 (God Object Anti-pattern)
*   **위치:** [`server/controllers/searchController.js`](../server/controllers/searchController.js)
*   **문제:** 하나의 파일에 Vision API 호출, SerpAPI 호출, 데이터 정제, 키워드 추출, 스크래핑 로직이 모두 섞여 있습니다.
*   **위험:** 코드 라인 수가 길어 가독성이 떨어지고, 유지보수가 어렵습니다.
*   **권고:** `services/imageAnalysisService.js`, `services/searchService.js` 등으로 비즈니스 로직을 분리해야 합니다.

### 🟡 2.2 스크래핑 로직의 취약성
*   **위치:** [`server/controllers/searchController.js`](../server/controllers/searchController.js)
*   **문제:** 정규식(`replace`)과 문자열 조작에 의존하여 데이터를 정제하고 있습니다.
*   **위험:** 쇼핑몰이나 검색 엔진의 HTML 구조/응답 형식이 조금만 바뀌어도 기능이 동작하지 않을 수 있습니다.
*   **권고:** 가능한 공식 API를 사용하고, 파싱 로직에 대한 예외 처리를 강화해야 합니다.

### 🟡 2.3 클라이언트 상태 관리 복잡도
*   **위치:** [`client/src/components/ImageEditor.jsx`](../client/src/components/ImageEditor.jsx)
*   **문제:** `useState`가 다수 사용되어 컴포넌트 내부 상태가 복잡합니다.
*   **권고:** `useReducer`를 사용하거나 커스텀 훅(`useImageEdit`)으로 로직을 분리하여 View와 Logic을 분리하는 것이 좋습니다.

---

## 3. 성능 (Performance)

### 🟡 3.1 이미지 처리 부하
*   **위치:** [`client/src/components/ImageEditor.jsx`](../client/src/components/ImageEditor.jsx)
*   **문제:** `handleUpscale` 함수 등에서 고해상도 이미지를 Canvas로 조작할 때 브라우저 메인 스레드가 차단될 수 있습니다.
*   **권고:** Web Worker를 도입하여 이미지 처리 연산을 백그라운드 스레드로 옮기는 것을 고려해볼 수 있습니다.

### 🟢 3.2 불필요한 재렌더링
*   **위치:** [`client/src/pages/Home.jsx`](../client/src/pages/Home.jsx)
*   **문제:** 검색 결과(`results`)가 많을 경우 `ProductCard` 리스트 렌더링 시 성능 저하가 발생할 수 있습니다.
*   **권고:** `React.memo`를 사용하여 `ProductCard`를 메모이제이션하거나, 결과가 매우 많다면 가상 스크롤(Virtual Scrolling)을 도입하세요.

---

## 4. 결론 및 우선순위

현재 코드는 **기능 구현 중심의 프로토타이핑 단계에서는 매우 훌륭**합니다. 하지만 운영 환경으로 넘어가기 위해서는 다음 순서로 리팩토링을 진행하시기 바랍니다.

1.  **[보안]** JWT Refresh Token 구현 및 CORS 설정 강화
